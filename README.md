 # Questionario

# 1. Qual e a diferenca entre Working Directory, Staging Area e Repository?

O Working Directory e o local onde ficam os arquivos do projeto e onde fazemos as alteracoes. A Staging Area e como uma area de preparacao, onde colocamos os arquivos que queremos salvar no proximo commit usando o `git add`. O Repository e onde ficam registrados os commits e todo o historico das alteracoes do projeto.

# 2. Qual e a diferenca entre git commit e git push?

O git commit serve para salvar as alteracoes no repositorio local e registrar um novo ponto no historico do projeto. Ja o git push serve para enviar esses commits para o repositorio remoto, como o GitHub.

# 3. E possivel realizar varios commits antes de executar um git push? Explique.

Sim. Podemos fazer varios commits antes de usar o git push. Cada commit fica salvo no repositorio local com suas respectivas alteracoes. Depois, quando executamos o git push, esses commits podem ser enviados para o GitHub.

# 4. Por que e interessante realizar commits pequenos e descritivos?

Porque fica mais facil acompanhar o que esta sendo feito no projeto. Quando os commits sao pequenos e possuem uma mensagem que explica a alteracao, fica mais simples consultar o historico e entender o que foi feito em cada etapa.

# 5. O que acontece com os commits locais quando ainda nao executamos o git push?

Os commits continuam salvos no repositorio local do computador. Eles nao sao perdidos, apenas ainda nao foram enviados para o GitHub. Podemos continuar fazendo outras alteracoes e commits normalmente antes de executar o git push.

# 6. Como verificar, pelo GitHub, se os commits foram enviados corretamente?

Podemos entrar no repositorio do projeto no GitHub e verificar o historico de commits. Se o commit aparecer no GitHub com a mensagem correta e as alteracoes esperadas, significa que ele foi enviado corretamente.
